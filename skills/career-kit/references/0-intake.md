# Phase 0: Intake

Goal: one Candidate Profile that every later phase reads from. It replaces guesswork. The user fills it once and updates it as they go.

The template is `assets/candidate-profile-template.md`. Give it to the user as a file, or run it as a short interview.

## How to run intake

1. **Start from what they already have.** If the user attaches a resume, LinkedIn PDF or export, or an old cover letter, extract everything you can into the template first. Then ask only for what is still blank. Nobody should retype their resume.
2. **Ask in small batches.** Three to five questions per message, grouped by section. Required fields first.
3. **Mark what is unconfirmed.** If something is read from a document and not confirmed by the user (a date that looks off, an unclear title), write `[confirm]` next to it.
4. **Hand back the filled profile** as a file named `candidate-profile.md`, and tell the user to attach or paste it at the start of future sessions. If the environment has a project or persistent storage, offer to save it there.

## What each section is for

| Section | Why it matters |
|---|---|
| Target | Norms change with role, seniority, industry and region. Advice without these is generic. |
| Work history | The evidence base. Titles and dates must be what an employer would confirm. |
| Wins with numbers | The raw material for bullets and stories. Each number keeps its employer and time window. |
| Skills and tools | For keyword matching. Split into "used in real work" and "familiar". |
| Stories | Interview raw material. A few lines each is plenty. |
| Known gaps | Named early, they become judgment. Found by the interviewer, they become weakness. |
| Naming rules | Clients or employers that must not be named publicly, and how to refer to them. |
| Pay | Only needed in Phase 5. Never invent a number. |
| Writing preferences | Applied to everything drafted for them. |

## Fields needed per phase

Ask only for the missing fields of the phase you are in.

| Phase | Required | Helpful |
|---|---|---|
| 1. Judge | Resume (or LinkedIn for an audit), target role, region | Seniority, industry |
| 2. Target | JD, resume | Target, known gaps |
| 3. Produce | Resume, JD or target role, wins with numbers | Skills split, writing preferences, LinkedIn text |
| 4. Final check | The finished material, the JD | |
| 5. Interview | JD, resume or profile, interview date, round, interviewer name and title | Stories, known gaps, pay, naming rules |
| 6. After | What happened in the interview, interviewer names | Recruiter email thread |

## Keeping it current

When the user shares a new fact (a new number, a corrected title, a story), offer once to add it to the profile. When two sources conflict (resume says one date, LinkedIn another), ask which is right rather than choosing.
